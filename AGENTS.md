# AGENTS.md

Guide for agents (and people) working on Streaming Next. Read it before changing the code, and keep it up to date
when a rule changes.

## The project

Streaming Next is a Manifest V3 browser extension (Chrome and Firefox) that lists the channels the user follows on
**Twitch**, **YouTube** and **Kick**, shows who is live and notifies when they go live. See the [README](README.md) for
the features.

- Stack: [WXT](https://wxt.dev) 0.21, Vue 3 (`<script setup>`), Vuetify 4, Pinia, vue-i18n, axios, lodash, moment.
- Package manager: **Bun only** (`preinstall` runs `only-allow bun`). Node >= 22.
- The OAuth client secrets live in [streaming-next-back](../streaming-next-back) (Nitro, Cloudflare Workers), which
  exchanges the login codes and refreshes the tokens. It stores nothing. The extension calls it through
  `VITE_APP_API_BACK_URL`.

## Commands

| Command            | What it does                                                             |
| ------------------ | ------------------------------------------------------------------------ |
| `bun install`      | Installs and runs `wxt prepare` and the git hooks                        |
| `bun run dev`      | Development build with reload (`dev:firefox` for Firefox)                |
| `bun run build`    | `check` plus the production build in `dist/chrome-mv3` (`build:firefox`) |
| `bun run zip`      | Store package (`zip:firefox`)                                            |
| `bun run check`    | `vue-tsc` on the app, the tests and the node configs                     |
| `bun run lint`     | ESLint with Prettier, **zero warnings allowed**                          |
| `bun run test:run` | Vitest once (`test:dev` watch, `test:coverage`)                          |

The pre-commit hook runs `check`, `lint:staged` and `test:run`. Never skip it (`--no-verify`); fix what fails.
Before finishing any change run `check`, `lint` and `test:run`, they are the same steps of the pull request workflow
(plus `build`).

## Repository layout

```
src/
  entrypoints/       WXT entrypoints: background, popup, options, quick-dialog (+ its content script inject)
  background/        Service worker: auth (OAuth flows), fetchStream (alarm every 30 s), command, update
    handlers/        Badge count and notifications
    types/           Messages between the pages and the background
  pages/             Root component of each entrypoint (Popup, Option, QuickDialog)
  layouts/           App, simple and loading layouts
  components/        UI, one folder per feature (listStream, auth, views/<view>, <feature>Dialog, ...)
  composables/       useXxx shared logic (useYoutubeLives, useKickLives, useStreamOrder, ...)
  store/system/      The single Pinia store (useSystemStore) and its types
  services/
    base/            AxiosBase
    api/<provider>/  HTTP layer: base class, endpoints, events, types, <provider>Api.ts
    business/        Logic per provider (twitchBusiness, youtubeBusiness, kickBusiness), appBusiness dispatches
  types/             Storage keys (sync, local, session) and shared types
  utils/             util.ts (urls, OAuth urls, colors, helpers), icons.ts (custom SVG paths), quickDialog
  plugins/           vuetify (themes), i18n, pinia, api (401 handling), error (toastr), moment, toastr
  locales/           en.json, pt-BR.json (+ moment locale)
public/              icons/ and _locales/ (store name and description)
tests/               Mirrors src/, plus __utils__/ (mocks, servers, fixtures) and integration/
```

`src/auto-imports.d.ts`, `src/components.d.ts` and `.eslintrc-auto-import.mjs` are generated by the build, do not edit
them by hand (commit them when they change).

## Code style

Prettier (`.prettierrc`): no semicolons, single quotes, 2 spaces, `printWidth` 120, `trailingComma: es5`, **LF line
endings**. On Windows, make sure scripts and editors keep LF (Python text mode writes CRLF).

- TypeScript strict, with `noUnusedLocals` and `noUnusedParameters`. Prefix intentionally unused parameters with `_`.
- Type-only imports use `import type` (`@typescript-eslint/consistent-type-imports` is an error).
- Imports use the `@/` alias for `src` and `@tests/` for `tests`. No relative imports across folders.
- The Vue APIs (`ref`, `computed`, `watch`, `onMounted`, `nextTick`, ...) are auto-imported, do not import them.
  Components and Vuetify components are auto-registered too, but the code imports its own components explicitly.
- WXT auto-imports are off (`imports: false`): import `browser` from `wxt/browser` and the `define*` helpers from
  `wxt/utils/...`. Never use `chrome.*` directly.
- Vue: `<script setup lang="ts">`, `defineProps<{...}>()`, `defineEmits<{...}>()`, `defineModel`. Template attributes
  follow `vue/attributes-order`. Components are PascalCase files, composables `useXxx.ts`.
- Icons come from `@mdi/js` as SVG paths (`:icon="mdiStar"`), icons missing there go in `src/utils/icons.ts` with the
  same shape (for example `mdiKick`). No icon fonts.
- Colors come from the Vuetify theme (`themes/dark.ts`, `themes/light.ts`), each platform has its color (`twitch`,
  `youtube`, `kick`), use `accountTypeColor(type, bg?, text?)`.
- Small exported objects with methods for the business layer (`const XBusiness = { async auth() {...} }`), classes for
  the HTTP endpoints (`class XApiChannelEndpoint extends XApiBase`).
- Prefer lodash helpers already in use (`uniqBy`, `orderBy`, `compact`, `cloneDeep`, `debounce`) over hand-written ones.

### Comments

Comments are in English, short, and explain **why** (a platform limit, a browser quirk, a quota), never what the next
line does. The code has few of them: match the density of the surrounding code. JSDoc (`/** ... */`) on exported
functions only when the contract is not obvious (for example "rejected with 401 when ..."). No commented-out code.

### Language

Code, comments, commit messages, test names and docs are in **English**. User-facing text is always translated (below).

## Architecture rules

### Platforms (accounts)

`AccountStoreType = 'twitch' | 'youtube' | 'kick'` and `ACCOUNT_STORE_TYPES` drive everything. There is at most one
account per platform in `accounts` (sync storage). Each platform has:

- `services/api/<provider>/`: `<Provider>ApiBase` (extends `AxiosBase`, adds the error interceptor that emits to
  `events/<provider>ApiEvent`), endpoints, types mirroring the API (snake_case kept), `<provider>Api.ts`.
- `services/business/<provider>Business.ts`: maps the API types to the list items (`StreamItemLive*Type`) and holds
  the caches and limits of that platform.
- A branch in `appBusiness.handlerAccounts` for each operation it supports.

Platform differences that must be respected:

| Platform | Followed list                                                          | Lives                                                        | Notes                                                                       |
| -------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Twitch   | API (`channels/followed`)                                              | `streams/followed`                                           | Token validated every hour (Twitch rule). Videos, clips, categories, search |
| YouTube  | Subscriptions (cached 30 min)                                          | RSS feeds + `videos` endpoint (cached 2 min), never `search` | Tiny API quota: cache everything, `youtube.com` optional host permission    |
| Kick     | **None in the API**: slugs added by the user (`kickChannels` sync key) | `channels?slug=` (same request as the channels)              | Only the category name, no `gameId` (the categories view is Twitch only)    |

Only Twitch has categories (`gameId`), videos and clips. Game notifications match categories **by name**
(`isSameCategoryName`), so they work across platforms.

### Adding a platform (checklist)

1. `AccountStoreType`, `ACCOUNT_STORE_TYPES`, the `type` unions in `streamItemType.ts`.
2. `.env` (API url, OAuth url, client id) and `vite-env.d.ts`. An empty client id hides the login (`isXEnabled()`).
3. `utils/util.ts`: OAuth url (with PKCE when supported), revoke request, profile url, `accountTypeColor`,
   `accountProfileUrl`, `streamItemProfileUrl`.
4. `background/authBackground.ts` (login and revoke), `BackApi.tokens`, and the routes in streaming-next-back.
5. API layer, business, `appBusiness` branches, `plugins/api` (401 handler of its event).
6. A `useXLives` composable, merged into `StreamsView` and `QuickDialogView`; `fetchStreamBackground` and
   `notificationHandler` (history and click).
7. `AuthActions.vue`, the icon in `StreamListItem` and `StreamTypeFilters`, theme colors (dark and light).
8. `manifest.config.ts` CSP (`connect-src` and `img-src`), locales, README and tests.

### Authentication and tokens

- Logins use the **authorization code flow**, started by the background (`launchWebAuthFlow`), because the popup can
  close during the login (Firefox). The `state` comes from `generateState()` (crypto random) and is checked.
- PKCE (`pkceChallenge`) whenever the provider supports it (YouTube and Kick; Twitch has none).
- The code exchange and the refresh go through streaming-next-back (`TokenBusiness`), the client secret never goes into
  the extension.
- `AccountStore.expiresAt` is renewed 5 minutes before it expires (`renewAccountToken` on the pages, `ensureToken` in
  the background). A rotated refresh token replaces the stored one.
- A 401 means: renew when there is a refresh token, mark the account `invalid` otherwise. A network or 5xx failure must
  **never** log the user out, it tries again later.
- Removing an account revokes the token (the refresh token for Google and Kick).

### Background

- `fetchStreams` runs on the `fetchStream` alarm (every 30 s). Do not recreate the alarm on wake-up (`ensureAlarm`).
- A failure of one platform (quota, network) must not hide the lives of the others; each one is fetched in its own
  `try`.
- Pages talk to the background with typed messages (`backgroundMessageType.ts`): add the type to the union and handle
  it in a `switch`. Messages to a popup that may be closed use `.catch(() => undefined)`.

### Storage

| Area      | Keys file                    | For                                                                                    |
| --------- | ---------------------------- | -------------------------------------------------------------------------------------- |
| `sync`    | `syncStorageKeysTypes.ts`    | User data synced between devices: accounts, favorites, groups, notifications, settings |
| `local`   | `localStorageKeysTypes.ts`   | Caches (followed streams, YouTube subscriptions and lives)                             |
| `session` | `sessionStorageKeysTypes.ts` | Online history of the notifications                                                    |

- Every key is a `STORAGE_KEY_*` constant with its type in the `Storage*Types` map. Never use string literals.
- The sync storage has a small write quota (and 8 KB per item): write only on user changes (`saveSync`), never on load,
  and keep the values small (ids and slugs, not whole objects).
- Store values are written with `cloneDeep` (Vue proxies can't be cloned by the storage).
- Caches of an account are discarded when they belong to another account (`accountId`).

### Store

`useSystemStore` (setup store) is the only store. It holds the screen/view state, the synced data and the actions that
save it. New persisted state: a `ref`, load it in `init`, a setter or action that calls `saveSync`, and export it in the
returned object (grouped by the existing comments).

### UI

- Popup, options and quick dialog share the components; the quick dialog runs inside an iframe on any page (its own CSP
  limits, no `autofocus`).
- Errors shown to the user use `toastr` (`toastr.error(t('...'))`); unexpected errors go to the error plugin.
- Dialogs follow the pattern of `GroupStreamDialog` (`v-dialog` with an `activator` slot, `defineModel` for open).
- Accessibility: buttons with only an icon need `aria-label` (and a `v-tooltip`); toggles use `role="checkbox"` with
  `aria-checked`. Tests select by `aria-label` and `data-testid`, keep them stable.
- `data-testid` names are kebab-case (`kick-auth`, `stream-type-twitch`).

### i18n

- Every user-facing string goes in **both** `src/locales/en.json` and `src/locales/pt-BR.json`, with the same keys.
- Keys are grouped by component or view (`kickChannelsDialog.title`) and **sorted alphabetically** inside each object.
- Plurals use the vue-i18n pipe syntax (`"Viewer | Viewers"`).
- The store name and description are in `public/_locales/<locale>/messages.json`.

### Manifest and security

- The CSP is built in `manifest.config.ts`. A new API or image host must be added there (`connect-src`, `img-src`).
- New permissions break existing installs (Chrome disables the extension until accepted): prefer
  `optional_host_permissions` requested on a user click, like the YouTube feeds.
- Never log tokens, never put tokens or user data in URLs other than the provider's own API.

## Tests

Vitest with jsdom, `@vue/test-utils`, WXT's `fakeBrowser` (the storage and runtime are in memory and reset per test).

- Files: `tests/<same path as src>/<Name>.spec.ts`, integration flows in `tests/integration/`.
- Names: `describe('Component.vue')`, `it('Render ...')` written as sentences starting with a capital letter.
- HTTP: `mockHttp()` from `tests/__utils__/http.ts` replaces the axios adapter, keeping the real interceptors. Use the
  in-memory servers (`twitchServer`, `youtubeServer`) and the fixtures (`account`, `apiStream`, `onlineItem`, ...);
  extend them instead of mocking modules.
- Components: `mountWithStore(Component, { props, state })`. Overlays (menus, dialogs) render in `document.body`: use
  `bodyFind`, `bodyFindAll`, `bodyFindByText`, then `settle()` / `flushPromises()`.
- Every feature or fix comes with tests; a bug fix gets a test that fails without it. Do not weaken or delete a test to
  make it pass.

## Git and releases

- Branches: `main` (released), `dev` (next minor), `fix/<name>` (patch). Work on `dev` or a `fix/` branch, never on
  `main`.
- When a pull request from `dev` or `fix/*` is merged into `main`, the build workflow bumps `package.json` (minor for
  `dev`, patch for `fix/`), builds and tags `vX.Y.Z`. Do not bump the version by hand.
- Commit messages: a short title in the imperative, in bold for features and refactors (`**Add Kick platform
integration**`), then a blank line and `-` bullets describing the changes. Small changes can use a plain one-line
  title.
- Commit only when asked, and never commit secrets: the `.env` holds only public values (urls and OAuth client ids),
  the client secrets belong to the backend.
